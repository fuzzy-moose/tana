# Domain Docs

## Before exploring

Read root `CONTEXT.md` and relevant decisions in `docs/adr/`.

If absent, proceed silently. Domain-modeling creates these lazily
when terminology or decisions are resolved.

## Layout

Single-context:
- `CONTEXT.md`: domain glossary and model.
- `docs/adr/`: numbered architecture decision records.

## Vocabulary

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. Reconsider unfamiliar terms; note genuine
glossary gaps for domain-modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR,
referencing the decision and explaining why reopening it is warranted.
