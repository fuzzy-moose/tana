# Collector keeps the Panda seen state

The unseen view of the Panda catalog must test each candidate gallery inside the collector's catalog page query, so the page fills in catalog order and stops at its limit. [ADR 0018](0018-postgresql-storage.md) keeps Tana's and the collector's databases separate, and passing Tana's seen galleries to the collector would send a growing list on every page. The collector therefore keeps the user's seen state for the Panda catalog, beyond the Panda metadata and archives it owns under [ADR 0004](0004-collector-owns-panda-data.md), and Tana reaches that state only through the collector API.

Display records and catch-up coverage are separate facts. Each display keeps its own time; a catch-up is one catalog position that only advances, with the time of the catch-up that set it. Neither references catalog rows, so the seen state survives every projection change, including provisional-to-collected replacement and removal and re-projection of a row. Identity is the gallery ID, so a new version of a seen gallery is unseen.

The collector keeps the Panda score model, its threshold and the score overrides with the seen state, because the score filter tests each candidate inside the catalog page query, and the model is calculated from the Panda favorites and the catalog the collector holds. Tana sends its default filter with each preview request, because the filter limits both the favorites and the catalog the model learns from; the collector keeps the catalog counts of the last filter it received under [ADR 0020](0020-collector-keeps-catalog-scope-counts.md). Weights and tag overrides reference the tag vocabulary, which projections only extend, and no gallery row, so they survive every projection change. The collector stores no score per gallery.

The collector keeps the pinned weights with the score overrides, because both are the user's judgments and the score filter reads them for each candidate inside the catalog page query. A pinned weight names its tag by the tag vocabulary, or keeps its uploader or category as text, and references no model and no gallery row, so it survives every projection change, every calculation and every change of the active model. The author bonus, the minimum weight of every favorite author's tag, is kept with the pinned weights for the same reason.

The collector keeps the set of favorite authors in a table of its own, read from its favorites and the catalog's tags in the transaction that completes a Panda favorite sync, so that the catalog page query probes one row per tag and never counts favorites per candidate. Only a completed full re-sync removes an author.
